## 1. 设计目标与约束

| 目标 | 转译为可执行要求 |
|---|---|
| 可信 | 每个资源旁可看到来源、核验日期、状态徽标；官方入口与普通外链视觉上可区分但不可喧宾夺主 |

| 有辨识度 | 识别来自信息组织方式（档案分节、索引行、双轨徽标、等宽技术信息），不来自配色和装饰 |
| 可扩展 | 10 款游戏不空、500 款游戏不乱——靠"行"和"分节"而非封面墙 |
| 低维护 | 全站零图片也可成立；封面为可选装饰位 |
| 静态可实现 | 不依赖后端/账号/外部字体/远程图库/复杂动画 |

## 2. 最终视觉方向：「活页索引档案」

### 2.1 方向定义

**整体气质**：一本维护良好的技术索引手册——介于 PCGamingWiki 的实用与优秀文档站的清晰之间，但用中文编辑式排版和状态标记系统拉开差异。它是"工具书"，不是"杂志"或"娱乐站"。

**五个构成性决策**（视觉识别由此产生，而非来自主题色）：

| # | 决策 | 说明 |
|---|---|---|
| D1 | **文档分节取代卡片盒** | 内容用「小节标题 + 细分隔线 + 留白」组织；卡片仅用于真正的入口/条目单元，绝不把页面切成等大的盒子墙 |
| D2 | **索引行为基本单元** | 列表内容以"行"呈现（名称+元数据+状态+操作一行完成），信息密度高、可扫读、可无限增长；网格卡片只出现在"精选/推荐"等限量场景 |
| D3 | **双轨徽标系统** | 生命周期=**实心小胶囊**；链接健康/核验=**描边小胶囊**。形状即维度——不看颜色也能区分"活动状态"与"链接状态" |
| D4 | **等宽字体表达技术信息** | 存档路径、报错码、日期、版本号一律 `ui-monospace`——这是"档案感"的字体签名 |
| D5 | **单一品牌色 + 状态色降级** | 全站主交互色只有"索引蓝"；状态色仅用于徽标/提示块等小面积，永不铺满区块 |

### 2.2 回答设计任务书

- **第一眼应该看到**：搜索框和"这个站能干什么"的一句话——不是banner，是功能本身
- **专业与可信怎么体现**：每条资源带核验日期和来源、状态徽标成体系、官方入口有明确标注、没有夸大营销词
- **无图识别**：文字封面（游戏名首字+类型色条）、索引行结构、双轨徽标——不依赖任何外部图片
- **首页/档案/索引为何同系统**：三者共用同一套"索引行+分节+徽标"语言，密度和容器宽度不同而已
- **与游戏导航站/下载站的实质区别**：它们以"图+按钮"卖资源位；本站以"行+状态"卖信息可信度——无广告位、无推荐流、无封面瀑布

## 3. 色彩系统

### 3.1 基础 Token（浅色主题，v1 唯一主题）

| Token | HEX | 用途 | 限制 |
|---|---|---|---|
| `bg-base` | `#FAFAF8` | 页面主背景（纸色微暖） | 全站唯一页底色 |
| `bg-raised` | `#FFFFFF` | 浮起层：下拉、抽屉、弹层 | 不用作大区块底色 |
| `bg-sunken` | `#F1F2EF` | 内嵌区：代码/路径块、表头底、速查条底 | 仅小面积内嵌 |
| `text-primary` | `#1D2129` | 正文、标题 | 对比度约 15:1 |
| `text-secondary` | `#4E5969` | 次要文字、说明 | 对比度约 6.9:1 |
| `text-tertiary` | `#646C78` | 元数据、核验日期、辅助 | 公式计算：vs `bg-base` 5.1 / vs 白 5.3 / vs `bg-sunken` 4.7 / vs `accent-soft` 4.6——**全场景 ≥4.5**（由 #86909C→#6B7280→#646C78 两轮上调；#6B7280 在 sunken/accent-soft 底仅 4.2–4.3 不达标）；仅限四种中性浅底使用，状态色底（`state-*`）上禁用、用该状态文字色；≥13px，不用于正文 |
| `border` | `#E4E6E9` | 装饰性分隔线、表线、非关键描边 | 1px 浅线（vs 背景约 1.2:1），不承担控件识别职能 |
| `border-control` | `#7E8793` | 输入框、下拉、描边按钮、筛选控件等需辨识的控件边框 | vs `bg-base` 约 3.5:1、vs 白约 3.7:1、vs `bg-sunken` 约 3.2:1（满足控件 ≥3:1；计算值待实机核验） |
| `accent` | `#2F5BD7` | 主交互：按钮、链接、选中、focus | 不做大面积铺色 |
| `accent-hover` | `#1F46B8` | 悬停/按下 | — |
| `accent-soft` | `#E9EFFB` | 选中态底、tag 底 | 不用于状态徽标 |
| `success` | `#1E7F4F` | 进行中、正常状态 | 仅徽标/图标/提示块 |
| `warning` | `#A05E00` | 待核验、疑似失效、截止不明、风险提示 | 仅小面积 |
| `danger` | `#B93A32` | 已失效、错误 | 仅小面积 |
| `info` | `#35618F` | 未开始、信息提示 | 仅小面积 |
| `neutral-badge` | `#5B6470` | 已结束、无状态类徽标 | 灰阶 |

**规则**：
- 生命周期与链接健康通过**徽标形态**区分（实心/描边），不靠颜色区分——同色可出现在两轨但含义不冲突（§9 详表）
- 状态色只出现在徽标、提示块、状态点；禁止用状态色做区块背景
- 红/黄/绿徽标总面积控制在页面可视区 5% 以内（自然达成：徽标很小）
- **对比度口径**：上表及 §11 所列对比度均为 WCAG 相对亮度公式计算值，未经实机渲染核验——实机效果列入实施验收，不达标再上调。实心徽标**白字**与状态底色的计算值：success `#1E7F4F` 5.00 / warning `#A05E00` 5.13 / danger `#B93A32` 5.65 / info `#35618F` 6.45 / neutral `#5B6470` 6.00 / accent `#2F5BD7` 5.84——均 ≥4.5:1。`border #E4E6E9` 与背景对比仅约 1.2:1，属装饰线，故控件边框一律走 `border-control`

### 3.2 文本与链接

正文 `text-primary`；说明 `text-secondary`；日期/来源 `text-tertiary`；链接 `accent` + 悬停下划线；外链统一 `↗` 上标符号 + 站名；已访问链接不变色（索引站无"未读"语义）。

## 4. 字体与排版

### 4.1 字体栈（全部系统字体，零外部依赖）

| 用途 | 栈 |
|---|---|
| 中文正文 | `"PingFang SC","Microsoft YaHei","Noto Sans CJK SC","Source Han Sans SC",sans-serif` |
| 英文/数字 | `system-ui,"Segoe UI",Roboto,"Helvetica Neue",Arial` |
| 等宽（路径/报错/日期/版本） | `ui-monospace,"Cascadia Mono",Consolas,"Courier New",monospace` |

数字与日期额外启用 `font-variant-numeric: tabular-nums`（表格对齐）。

### 4.2 字号层级（基准 16px）

| 级别 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| H1 页标题 | 28px / 1.3 | 700 | 页名、档案名 |
| H2 模块标题 | 20px / 1.35 | 700 | 详情页各模块（获取渠道、MOD与汉化…） |
| H3 小节标题 | 16px / 1.4 | 600 | 分区内子标题、步骤题 |
| 正文 | 15px / 1.75 | 400 | 简介、说明、教程内容 |
| 次要 | 14px / 1.6 | 400 | 卡片说明、列表副行 |
| 元数据 | 13px / 1.5 | 400 | 核验日期、来源、版本 |
| 徽标/标签 | 12px / 1 | 500 | 状态徽标、tag |
| 大数字/速查 | 15px | 500 mono | 路径、报错码 |

字距：正文默认；标题 `-0.01em`；徽标 `+0.02em`。标题换行：中文任意字间断行，避免单行孤字（`text-wrap: balance` 思路）。长名：索引行内中文名一行省略（`ellipsis`），详情页头部允许多行。长 URL/路径：`word-break: break-all` + mono。

### 4.3 元数据排版惯例

- 日期统一 `YYYY-MM-DD` 等宽体，前置动词：`核验于 2026-10-20`
- 来源：`来源：PCGamingWiki ↗`（站名+↗），多来源竖排小列表
- 平台/系统：小型文字 tag（`accent-soft` 底 + `text-secondary` 字），非徽标体系

## 6. 边框、圆角、阴影、图标、动效

| 项 | 规则 |
|---|---|
| 边框 | 分工明确：装饰性分节线/表线/非关键描边=1px `border`；**可辨识控件（输入框、下拉、描边按钮、筛选控件）=1px `border-control`**；不用边框圈大区块 |
| 背景分层 | `bg-sunken` 仅用于内嵌技术块（路径/报错）与表头行 |
| 圆角 | 按钮/输入/徽标/小卡片 = 6px；大行容器/抽屉 = 8px；正文区块无圆角；徽标用全圆角胶囊（999px） |
| 阴影 | 仅浮层（下拉、移动抽屉、提示气泡）：`0 2px 8px rgba(29,33,41,.08)`；**页面内容零阴影** |
| 图标 | 线性图标，1.5px 描边，16px，与文字基线对齐；站内导航可用图标+文字；外链统一 `↗` 上标字符不用图标库 |
| 徽标 | 全圆角胶囊，12px 字，`padding 3px 8px`；生命周期=实心（彩色底白字），链接健康/其他状态=描边（彩边彩字浅底） |

| 场景 | 触发 | 时长/效果 |
|---|---|---|

| 菜单项当前态 | 路由切换 | 无动画 |

## 7. 全部 13 种页面视觉设计

> 格式：页面目标 / 首屏层级 / 结构线框 / 模块顺序 / 核心操作 / 视觉优先级 / 数据状态变化 / 桌面+移动 / 最易设计错误。
> 线框图例：`█`主操作 `▤`内容区 `─`分隔 `·`元数据。

### 7.1 首页 `/`

**目标**：3 秒定位 + 一步进入分流。**视觉重心：搜索框**。浏览路径：搜索→分流→样板/时效内容→页脚。

```
┌ 顶部导航 ─────────────────────────────┐
│ 玩机索引      游戏库 免费 资源站 工具 教程   [搜索] │
├──────────────────────────────────────┤
│            玩机索引（H1, 28px 大留白）       │
│      找游戏 · 找资源 · 解决问题（一句定位）    │
│      ┌ ████████████ 大搜索框 ████████ ┐   │
│         搜游戏名、报错、工具…             │
├──────────────────────────────────────┤
│ 从这里开始 ▏五个分流入口（文字列表式，非卡片墙）│
│  ▸ 找游戏      —— 浏览全部游戏档案          │
│  ▸ 找免费      —— 限免/试玩/开源          │
│  ▸ 找 MOD/汉化 —— 资源站·MOD社区          │
│  ▸ 找工具      —— 存档/MOD管理/修复        │
│  ▸ 游戏出问题   —— 报错排查与教程          │
├──────────────────────────────────────┤
│ 精选游戏档案（H2）                       │
│  ▤ 索引行×6-8（编号式档案行，非封面卡）      │
├──────────────────────────────────────┤
│ 免费游戏快报（H2） ·最近构建日期           │
│  ▤ 条目行×3-5：游戏名·类型徽标·截止·█领取↗  │
│  （无有效活动→列表隐藏，保留"实时追踪→"行）   │
├──────────────────────────────────────┤
│ 热门工具（H2）    │  最近更新（H2）        │
│  ▤ 紧凑行×4-6    │  ▤ 更新行×5-8        │
├──────────────────────────────────────┤
│ 页脚：收录原则一句·关于·反馈·sitemap·版权    │
└──────────────────────────────────────┘
```

- **模块顺序**：导航 → Hero(搜索) → 分流 → 精选档案 → 免费快报 → 工具+更新双栏 → 页脚
- **视觉优先级**：搜索框（最大控件+最多留白）＞ 分流文字列表 ＞ 档案行/快报 ＞ 工具/更新
- **数据状态**：精选/快报/工具/更新任一缺数据 → 该模块整体消失，其余自然上移；**首页在 10 款游戏时也完整**——因为每个模块都是"行"，行数少不空洞
- **桌面**：1120px；分流入口呈 2 列文字列表（右列说明文字）；工具/更新左右 1:1 双栏
- **移动**：单列；分流 5 条全宽行；工具/更新上下堆叠
- **最易错**：把分流做成 5 个等大彩色卡、把精选做成封面瀑布、Hero 塞大背景图——全部禁止；首页的"满"靠结构不靠素材

### 7.2 游戏库 `/games/`（索引页通式基准）

**目标**：快速定位或浏览全部游戏。**结构选型理由**：用"索引行"而非卡片网格——行可展示名称/别名/类型/资源数/核验五要素于一目，500 款时不退化为图片墙。

```
┌ 游戏库（H1）  已收录 N 款 ─────────────────┐
│ ┌ 页内搜索 ┐ [类型▾][平台▾][排序:名称▾]      │
├──────────────────────────────────────┤
│ ▤ 索引行：星露谷物语 Stardew Valley        │
│   simulation·rpg  MOD3 工具2 教程1 ●已核验  →│
│ ─────────────────────────────────────│
│ ▤ 索引行 ×n                            │
├──────────────────────────────────────┤
│ 空态：未找到「xx」·当前条件·[清除全部]·提交收录 │
└──────────────────────────────────────┘
```

- **行结构**：左=中文名(15px 500)+英文名(13px tertiary)；中=类型 tag×2；右=资源计数小标(mono 13px)+核验点+`→`
- **筛选条**：即时搜索框(左侧最大)+筛选下拉+排序下拉；激活条件在下方以可除标签呈现
- **空态**：当前条件摘要 chips + 清除按钮 + 收录请求链接，居中但内容完整
- **移动**：行转两行式（名+类型上行，计数+状态下行）；筛选收进抽屉按钮
- **最易错**：做成封面卡片网格（图片依赖+低密度）；筛选器在移动端常驻占半屏；省略号截断中文名却不给悬停全称

### 7.3 游戏详情页 `/games/{slug}/`（全站核心）

**目标**：一页回答"去哪买/免费吗/MOD在哪/报错怎么办/存档在哪"。**长页面靠分节节奏，不靠卡片。**

```
┌ 面包屑 首页/游戏库/星露谷物语 ─────────────┐
│ [文字封面块] 星露谷物语（H1 28px）          │

│ ▤ 表行：Steam│购买│¥48│核验10-01│█ 前往↗   │
│ ▤ 表行：官方站│试玩│免费│核验10-01│█ 前往↗  │
├──────────────────────────────────────┤
│ 常见问题（H2）— 可折叠列表               │
│  ▸ 启动白屏怎么办？ → 教程内链            │

│ ▤ 紧凑行：SMAPI·MOD加载器·适用1.6│详情→│↗ │
```

- **视觉优先级**：档案头名称 ＞ 获取渠道表（含限免提示条）＞ 速查条/FAQ ＞ 资源区 ＞ 相关区
- **官方入口突出方式**：获取渠道用**结构化表格**+实色"前往 ↗"按钮——全站只有"获取/领取"动作用实色按钮，其余外链一律文字链+↗；这就是"官方 vs 普通"的区分手段（按钮层级差异而非颜色差异）
- **模块收缩**：任一模块无数据 → 标题+分隔线整块不出现，页面自然缩短
- **失效处理**：死链行整行降级——按钮禁用灰化+"已失效"描边徽标+替代去向，仍占位以便反馈
- **桌面**：800px 单栏；渠道表 5 列
- **移动**：渠道表降级为卡片行（平台名+类型徽标一行，按钮整宽）；速查条路径可横向滚动（mono 不换行截断式）
- **最易错**：每个模块都做成卡片（分节感丢失）；限免提示条做得像广告横幅；已失效条目直接删除导致用户以为信息缺失

### 7.4 免费游戏 `/free/`

**目标**：五类免费准确分区 + 时效诚实。**关键呈现决策（`?type=` 多选后）**：

| 方案 | 阅读效率 | 重复信息 | 空态 | 移动端 | 结论 |
|---|---|---|---|---|---|
| A. 保持五分区，过滤后各区只显示命中 | 低——跨区滚动找命中项，空分区占屏 | 高——每区重复类型标题 | 复杂——部分区空部分有 | 差 | ✗ |
| B. 任一筛选激活 → **统一筛选结果列表** | 高——单一有序列表 | 无 | 简单——一个空态 | 好 | **✓ 采用** |

**规则**：默认（无 `?q=`/`?platform=`/`?type=`）→ 五分区浏览视图；任一筛选激活 → 切换为统一结果列表（条目自带类型徽标，类型信息不丢失）；清除全部 → 恢复分区视图。**纯呈现切换，不改变 §03-7.4 筛选与 URL 规则。**

```
┌ 免费游戏（H1）  本页最近构建 2026-10-23 ──┐
│ 五种免费类型说明（一行小字）               │
│ ┌ 关键词 ┐ [平台▾][类型▾] [清除全部]       │
├─ 分区视图（默认）─────────────────────────┤
│ ▸ 限时领取（锚点）                        │
│  ▤ 条目行：游戏名│epic│●进行中 剩2天│核验   │
│            领取条件句            █ 前往领取↗│
│ ▸ 永久免费 / 免费试玩 / 免费周末 / 开源     │
├─ 筛选视图（有参数时）──────────────────────┤
│ ▤ 命中行列表（同条目行结构+类型徽标）        │
├──────────────────────────────────────┤
│ 实时追踪入口：ITAD↗ SteamDB↗ Epic免费↗    │
│ ▾ 已结束（N）折叠区：置灰行·结束日期        │
└──────────────────────────────────────┘
```

- **条目行字段序**：游戏名 → 平台 → 生命周期徽标 → 截止（mono 醒目）→ 领取条件 → 核验日期 → 链接徽标 → CTA
- **生命周期徽标（一律实心胶囊）**：进行中=success、未开始=info、已结束=neutral、截止不明=warning、状态待确认=warning——五者同为实心形态，以文字区分；与描边的链接健康/核验徽标形态不同轨
- **permanent/opensource**：无生命周期徽标，只有类型徽标+链接健康
- **最易错**：限免条用大红促销色；把"已结束"混进有效列表；永久免费也挂"进行中"徽标

### 7.5 资源站索引 `/resources/`

- 同 §7.2 索引行模式：行=站名(中/英)+分类徽标+简介一句+语言/费用 meta+关联数+`详情→`+`访问↗`（双操作）
- 顶部 8 分类 tab（带计数）而非下拉——分类是主要浏览维度
- **最易错**：做成"图标+域名"网址导航列表（丢失分类/用途/核验信息层）；`详情` 与 `访问` 不做视觉区分（内链用次级按钮，外链用文字链+↗）

### 7.6 资源站详情 `/resources/{slug}/`

- 800px 文档页：档案头（名+分类+官网入口——**文字链+↗**，以位置与字号突出而非实色按钮）→ 信息块（labeled list：用途/语言/费用/限制/风险）→ 关联游戏 chip 链 → 关联入口列表 → 核验行+反馈
- 风险提示用 §8 的**警示条组件**（warning 左边框+文字，不红不吓人）
- **最易错**：做成游戏档案页翻版（站点不是游戏：无渠道表、无 MOD 区）；关联游戏列表缺失时忘了隐藏

### 7.7 工具库 `/tools/` 与详情 `/tools/{slug}/`

- 索引同 §7.2：行=名称+类型徽标+用途一句+OS tag+`详情→`+`官网↗`
- 详情（800px）：头（名+类型+OS tag+`█官方获取↗`）→ 功能列表（勾选项式列表）→ 安装要点（编号步骤）→ 兼容/版本（待核验徽标兜底）→ **风险警示条**（如"仅限单机，联机使用可能封号"）→ 相关游戏/教程 → 核验行
- **最易错**：风险条做成红色 alert（应克制 amber 左边框）；版本号未知却显示具体数字

### 7.8 教程列表 `/guides/` 与详情 `/guides/{slug}/`

- 索引行=标题+类型徽标+关联游戏+核验日期
- 详情是**步骤文档**，节奏核心：

```
│ 标题（H1）  [问题排查] 适用：游戏X·Win11 │
├──────────────────────────────────────┤
│ 问题描述（bg-sunken 引用块）             │
│  现象……；报错原文 0xDEMO0001（mono 突出） │
├──────────────────────────────────────┤
│ ① 步骤标题                             │
│   操作：……                            │
│   预期：……                            │
│   若未解决 → 下一步去向（secondary 小字） │
│   [亲测]/[社区方案未核验] 描边徽标        │
│ ② …                                   │
├──────────────────────────────────────┤
│ 恢复方法 / 信息来源（外链列表）/ 相关区    │
└──────────────────────────────────────┘
```

- **最易错**：步骤合成一大段文字（必须用编号步骤块）；报错原文用普通字体（应 mono 突出，它是搜索锚点）；缺"若未解决"行

### 7.9 搜索结果 `/search/`

- 800px；顶部搜索框回填 → 分类 tab（全部 N｜游戏 n｜资源站 n｜工具 n｜教程 n）→ 分节结果：结果项=类型徽标+标题（命中词可加粗）+摘要一行+来源路径
- 状态：空引导态（热门词条可点）/ 无结果态 / **索引加载失败态**（错误图示+重试按钮+建议走索引页）——三态绝不混用
- `noindex` 页面，信息结构即完成度，不做额外装饰
- **最易错**：加载失败显示"无结果"；结果不分组一锅端

### 7.10 关于页 `/about/` 与 `404`

- `/about/`：800px 文档页；桌面左侧锚点目录（200px），移动顶部锚点链；分节=介绍/标准/核验/声明/反馈/联系，反馈节三渠道按钮式排列
- `404`：居中块：大字"404"+一句说明+三个去向入口（首页/游戏库/资源索引，**描边次级按钮**——站内导航不用实色主按钮）+搜索框+反馈链接行——恢复路径≥3 条

## 9. 统一状态视觉系统（§03 状态表 → 视觉映射）

**双轨规则**：生命周期=**实心胶囊**；链接健康/核验/数据状态=**描边胶囊**；二者从不混用形态。

| 状态 | 文字 | 形态/颜色 | 位置 | 可点击 | 替代操作 | 移动端 |

| 已失效 | 「已失效」 | 描边·danger+链接删除线 | 链接处，按钮禁用 | **否** | 替代入口+反馈 | 同 |

| 进行中 | 「进行中」 | 实心·success | 同上 | 是(█领取) | — | 同 |
| 已结束 | 「已结束」 | 实心·neutral | 归档区/置灰行 | 参考链接可点 | 实时追踪 | 同 |
| 截止不明 | 「截止不明」 | 实心·warning | 免费条目卡 | 是 | 官方页为准 | 同 |

## 10. 响应式规范

| 断点 | 范围 | 布局行为 |
|---|---|---|
| 桌面 | ≥1024px | 全布局；详情页 ≥1200px 加页内目录 |
| 窄桌面/平板 | 640–1023px | 容器自适应；索引行保持单行（右侧元数据可折行）；详情页无目录 |
| 移动 | <640px | 单列；索引行两行式；筛选全部入抽屉；渠道表转卡片行；按钮整宽 |

**细则**：
- 多列→单列：仅首页"工具/更新"双栏与分流双列在 <640 收单列
- 必须保留的元素（移动端不隐藏）：搜索框、状态徽标、核验日期、CTA 按钮、反馈入口
- 可降级元素：英文名/别名→缩到副行；资源计数→缩略形式；页内目录→隐藏
- 长名/长 URL：索引行省略+详情页断行；mono 路径块横向滚动
- 锚点跳转：`scroll-margin-top: 72px`（导航 56+余量）防遮挡
- 徽标过多：索引行最多显 3 个（类型+生命周期+链接），其余进详情页；移动端同类合并显示最关键一个+计数
- 渠道表→移动卡片行：平台+类型一行 / 价格+核验一行 / 按钮整宽一行

### 10.2 触控尺寸规则（视觉高度 ≠ 可点击区域）

| 元素 | 桌面端 | 移动端（<640px） |
|---|---|---|
| 实色/描边按钮 | 视觉高 36px，点击区 = 视觉框 | 视觉高 ≥44px；整宽按钮 H48 |
| 文字链（行内） | 继承行高 | 可点区 ≥44px——通过行高/padding 扩展，文字本身可保持 14px |
| 索引行 | H64–72，整行可点 | 整行可点 ≥48px（行高本就满足） |
| 筛选/排序按钮 | 视觉高 40px | 点击区 ≥44px（padding 补足） |
| 抽屉/面板关闭按钮 | — | 点击区 ≥44×44px（视觉图标可 20px，周围透明扩展区计入） |
| 复选/单选项 | 控件 16px+标签 | 整行可点 ≥44px |

### 10.3 首屏密度验收口径

- **基准视口**：1440×900（桌面）、390×844（移动）为验收参考视口
- **两个指标分开算**（不混淆）：
  - 「首屏可见条数」= 首屏内可辨识的条目行数（允许末行部分截断）
  - 「可完整操作条数」= 不滚动即可完整阅读并点击的条目数
- **测算**（桌面 1440×900）：导航 56 + 页内上边距 48 + 标题行 36 + 筛选条 44 + 间隙 32 ≈ 占用 216px；剩余 684px ÷ 行高 64px ≈ **10.7 行**——「首屏可见 ≥10」可达，「完整可操作」按 ≥9 验收；行高取 72px 密行时相应下降约 1 行
- **回退方案**：若实机核验不足，优先压缩页头间距（48→32）而非压缩行高/字号/触控区；不得为凑数量指标破坏可读性
- 移动端不考核条数指标，考核"首屏可见搜索框+首个条目"

## 11. 可访问性规范

- 对比度：正文 ≥4.5:1（公式计算值：primary 约 15、secondary 约 6.9、tertiary 在全部四种中性浅底上 4.6–5.3——均为计算值，实机渲染核验列入实施验收）；大文字/控件 ≥3:1；实心徽标白字 ≥4.5（见 §3.1 注）；tertiary 不得出现在状态色底/深底上
- 焦点：`accent` 2px 外描边，全控件可见；键盘可达全部交互
- 链接：`accent`+悬停下划线，不只靠颜色（hover/focus 均有线）
- 状态：颜色+文字+形态三重编码（徽标必有文字；双轨形态不同）
- 触达：移动可点目标点击区域 ≥44×44px（视觉高度可与点击区分离，见 §10.2）；索引行整行可点 ≥48px
- 表单：输入框有可见 label 或明确占位+aria-label；筛选控件带组标签
- 媒体：无自动播放任何媒体
- 动效：尊重 `prefers-reduced-motion`，关闭过渡/位移
- 缩放：200% 文字缩放下布局不破（索引行可增高，表转卡片）
