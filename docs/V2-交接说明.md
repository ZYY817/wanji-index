## 仍需人工完成的外部项

1. `config/site.json` 的 `url` 仍是部署占位地址。正式域名确定后只改这一处并重建。
2. `feedback.issueUrl` / `feedback.email` 暂为空。填入 GitHub Issues 地址或邮箱后，全站反馈链接自动启用并预填页面标题与正文模板；留空时关于页会明确提示渠道未开通，不产生死链。

## 维护入口

- 新增游戏 / 资源站 / 工具 / 教程 / 免费情报：README「新增内容」表；只改 `data/`，页面与索引构建时生成。
- 搜索口径：`src/lib/search-index.mjs`。游戏、站点、工具、教程入索引；Entry 关键词并入关联实体；Offer 按既定信息架构不入全站索引。
- 反馈渠道：`config/site.json` → `feedback`；实现集中在 `src/components/layout/feedback.tsx`。
- 截图验收：`node scripts/shots.mjs [路径...] --desktop|--mobile --steps=... --tag=...`，输出到 `.shots/`（不提交）。
- 发布前：`npm run build && npm test && npm run check:contrast`。

## 设计硬约束（继续遵守）

- 实心橙只给获取 / 领取 / 下载；生命周期徽标实心，状态徽标描边。
- SSR 文字全部可见；动效只动 transform / opacity；`prefers-reduced-motion` 下静止。
- 禁止背景光晕、紫蓝渐变、玻璃拟态、「图标 + 标题 + 描述」卡片阵列、原生 select、全站系统黑体。
- 站内链接用 `next/link`；原生 `<a>` 与 `fetch()` 用 `withBase()`；外链带 `target="_blank" rel="noopener noreferrer"`；`linkHealth === 'dead'` 时禁用并提供替代去向与反馈入口。
