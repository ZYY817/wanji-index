## 2. 技术栈选型

### 2.1 候选比较（三方案 + 自写对照）

| 维度 | **Astro** | Eleventy (11ty) | Hugo | 自写生成器 |
|---|---|---|---|---|
| 独立 HTML | ✅ 默认全静态 | ✅ | ✅ | 自建 |
| 中文 SEO/独立路由 | 文件路由+`getStaticPaths` | 分页/集合需自组装 | 可用但模板表达弱 | 自建 |
| JSON/MD 数据接入 | 原生 import + `import.meta.glob` | 全局数据层 | data 目录，多对多关系难写 | 自由 |
| 多实体关联/反查 | lib 同语言直接算 | 同左 | 模板内几乎不可行，需外挂脚本 | 自由 |
| 自定义校验 | 同语言 Node 脚本插桩容易 | 同左 | 双语言割裂 | 自由 |
| 客户端搜索/筛选 | 静态壳+JS 小岛，默认零 JS | 手写 | 手写 | 手写 |
| 模板/组件复用 | `.astro` 组件+Layout 贴合 05 组件体系 | njk/liquid | Go template 弱 | 自造语法 |
| SEO 产物（sitemap 等） | 官方集成 | 插件/手写 | 内建但定制弱 | 手写 |
| 构建速度 | 快 | 快 | 极快（规模内无差异） | 取决于实现 |
| 免费部署 | 官方支持 | 同 | 同 | 静态产物皆可 |
| 单人长期维护 | **低** | 中（plumbing 自理） | 高（双语言栈） | **最高（全量自维护）** |

### 2.2 结论：**Astro 为首选候选**（待 M0 前置技术验证后最终确认）

**理由**：本项目=数据文件驱动+多对多反查+自定义校验+客户端小岛交互。Astro 以单一 JS 生态覆盖数据加载/校验/模板/构建，是 11ty 要更多胶水、Hugo 要跨语言才能达到的同等能力。`getStaticPaths` 天然映射"每实体一 HTML"；默认零运行时 JS，只在搜索/筛选挂小岛。

**Astro vs 11ty 的关键差异**：11ty 的 collection/pagination 对"每实体一路由+反查模块"需要更多手工组装，组件化表达弱于 `.astro`；两者生态同为 JS，差异不大但 Astro 的组件模型与本项目 22 组件体系更贴合，官方 sitemap/redirects 集成也减少自写量。

**自写生成器**：灵活但需自维护模板语法、资源管线、增量构建、错误处理——对单人项目是最大长期负担，且无任何能力缺口非它不可。**评估淘汰**，仅作对照记录。

**不选 Hugo**：构建速度对本规模无收益；Go 模板表达反查/双轨徽标逻辑费力；校验需另写 JS 栈。

**结论成立的条件**：以下关键环节必须在 M0 前置技术验证（M0a）中实测通过——`getStaticPaths` 按资格集合生成页面、数据目录聚合加载、反查模块渲染、双轨徽标组件、`import.meta.glob` 读 JSON/MD。任一不满足则重评 11ty。

### 2.3 依赖边界

- 要：Astro + 原生 JS + **Ajv（JSON Schema 校验器）** + `@astrojs/sitemap`。总依赖 ≤4 个。
- 不要：TypeScript（JS+JSDoc 够用）、CMS/内容框架、数据库、UI 组件库、搜索库、CSS 框架。

### 2.4 数据校验实现方式（分层，推翻"全部手写单文件"）

| 层 | 工具 | 覆盖 |
|---|---|---|
| 结构校验（字段/类型/必填/枚举/格式） | **JSON Schema + Ajv**——每实体一份 schema 文件，随 Schema 演进只改 schema 不改代码 | 阻断级检查的主力 |
| 跨实体业务规则 | 手写 JS | 关联完整性、ID/slug 唯一、`_demo` 排除、最低发布标准 |
| 展示资格计算 | 手写 JS 函数 `lib/eligibility.mjs`（唯一判定处） | published∧达标∧非demo |
| 产物一致性检查 | 手写 JS `scripts/check-artifacts.mjs` | 索引↔页面、sitemap、redirects、demo 泄漏 |

JSON Schema 覆盖 04 的全部字段级规则；跨实体引用、资格、生命周期这类"不是单文件能断言"的规则走自定义代码。不引 TS，但不为省依赖而拒绝标准校验工具——Ajv 是成熟单依赖，换来 schema 即文档的可维护性。

## 3. 托管平台选型（额度核验于 2026-10-23 官方文档）

### 主方案：**Cloudflare Pages**

| 项 | 免费档现状 | 对本项目 |
|---|---|---|
| 构建 | 500 次/月、并发 1、超时 20min | 充裕 |
| 文件数 | ≤20,000 | 充裕（预计 <1,000） |
| 带宽 | 无显式上限 | 充裕 |
| **重定向** | `_redirects` 原生（≤2,000 静态+100 动态）；`404.html` 原生返回 404 | **命中 redirects.json→`_redirects` 生成路径** |
| 域名/HTTPS | 自定义域+自动证书 | ✅ |
| Git 部署 | push 即构建，控制台有日志 | ✅ |
| 预览/回滚 | 无限预览，可重发任一历史部署 | 天然回滚 |
| 短板 | 并发 1；国内访问"通常可用不保证" | 入风险表 |

### 备选：**GitHub Pages**

优点：仓库即站点、Actions cron 最短、`404.html` 支持、自定义域+HTTPS。缺点：100GB/月软流量；**无服务端重定向**（需 meta-refresh 页）；国内访问不稳；ToS 禁商业托管（本站非交易型不冲突）。

### 双平台真实差异（纠正"同一产物两边部署"的旧表述）

**同一源码、两种构建，不是同一产物**：

| 差异点 | CF Pages | GitHub Pages | 处理 |
|---|---|---|---|
| 部署路径 | 根路径 `/` | 项目站点为 `/{repo}/` 子路径（用户/组织站点才是根） | Astro `base` 参数按平台注入；**优先建议 GH 用户/组织站点形态保住根路径**，否则内链、canonical、sitemap、资源路径全部要按子路径重建验证 |
| 站点绝对 URL | `*.pages.dev` 或自定义域 | `*.github.io` 或自定义域 | `site` 参数按平台注入——canonical/JSON-LD/sitemap 内绝对 URL 随之不同 |
| 重定向 | `_redirects`（原生 301/302） | meta-refresh 页（无状态码概念） | 同源 `redirects.json` 生成两种格式；301/302 语义只在 CF 端成立 |
| 404 | 原生 404 状态 | 原生 404 状态 | 一致 |
| 域名未购时 | pages.dev 子域可用 | github.io 子域可用 | `site.url` 配置为当前实际域，迁移/换域时改配置重构建，canonical 全域换写 |

**迁移成本（如实）**：切平台 = 改 `site`/`base` 配置 → 重建 → 重新验收 redirects、404、canonical、sitemap、内链完整性——约半天配置与验证工作量，非零成本但可预期。

### 纯静态做不到的事（如实声明）

不能实时验证全部外链（构建期抽查/标 suspect 而已）；不能保证限免数据始终最新（快照+运行期补充+时效披露）；不能自承载表单（Issues/第三方表单/邮箱已定案）；无任何服务端个性化。

## 4. 项目目录与架构

```
webindex/                  # 仓库根
├── docs/                  # 阶段文档（人工）
├── data/                  # ★源数据（人工维护，每实体一文件）
│   ├── games/  sites/  entries/  tools/  offers/
│   ├── guides/            # *.json + 可选同名 .md 正文
│   ├── pages/about.md
│   └── _examples/         # ★示例数据：绝不进构建（加载层硬排除）
├── config/                # site.json / enums.json / redirects.json（人工，唯一定义点）
├── public/                # favicon、占位图等真静态资源（人工）
├── schemas/               # 每实体 JSON Schema（Ajv 用，人工维护）
├── scripts/               # validate.mjs / check-artifacts.mjs（人工，构建前执行）
├── src/
│   ├── pages/             # 路由=文件：13 种页面对应 .astro
│   ├── layouts/           # 8 模板（Base/索引/详情等）
│   ├── components/        # 徽标/索引行/外链按钮/空态…（05 §8 组件体系）
│   ├── styles/            # tokens.css + base.css（冻结 05 落地处）
│   ├── lib/               # 数据加载/反查/生命周期/eligibility/索引生成（构建期）
│   └── client/            # 搜索与筛选的原生 JS（全站唯一运行时 JS）
├── dist/                  # ★构建产物（自动生成，禁止手改，.gitignore 排除）
└── astro.config.mjs / package.json / package-lock.json
```

**人工 vs 生成边界**：人工只碰 `data/` `config/` `schemas/` `docs/` `public/` `src/` `scripts/`；`dist/`、HTML、索引、sitemap、`_redirects`、反查、buildTime 全为构建产物。**不得手编辑**：`dist/` 全部；`enums.json` 存储值一经发布不改。

**内容操作→文件对照**：新增=对应 `data/<type>/新文件.json`（教程可附 .md）；改内容=对应字段；核验=`checkedAt`+按需 `linkHealth`；下线=`publishStatus:"offline"`；改 slug=数据字段 **+** `redirects.json` 登记（必须成对）；改周期/站点信息=`config/site.json`；新增枚举=`config/enums.json` 先登记。

## 5. 静态页面生成与路由（严格沿用 02 路由表）

13 种页面对应 `src/pages/` 文件（`index`/`games/index`+`[slug]`/`free`/`resources/*`/`tools/*`/`guides/*`/`search`/`about`/`404`），机制：

- **统一资格函数**：`lib/eligibility.mjs` 实现 `可展示 = published ∧ 达标 ∧ 非 _demo`（04 §8.3 已定案），详情页 `getStaticPaths`、索引列表、关联模块、首页快报、搜索索引、Sitemap **全部消费同一结果**——模板不得各自过滤
- **按实体去向**（04 §8.3 表）：Game/Site/Tool/Guide→详情+索引+搜索+Sitemap；Entry→入口行展示（无详情/无独立搜索/无 Sitemap）；FreeOffer→`/free/`+快报（无详情/无搜索/无 Sitemap）
- **关联过滤**：反查模块只渲染资格集合内的被引用实体；下线/未达标/未发布实体的关联项**不渲染**（04 §6 统一规则）
- **模块隐藏**：无数据整节不输出 DOM（03 空态规则）
- **slug 变更**：改 `slug` 字段+登记 `redirects.json`→构建产出 `_redirects`（CF 301）与 meta-refresh 页（GH 备）

## 6. 搜索、筛选与客户端交互

### 6.1 全站搜索

- 构建期 `lib/search-index.mjs` → `/search-index.json`；仅收录资格集合内 Game/Site/Tool/Guide；Entry 名+关键词并入宿主 `linkedKeywords`；**FreeOffer 不进索引**；构建断言"索引项 URL 必有实有 HTML"
- 客户端 `?q=`→懒加载索引→归一化→名称>别名>关键词三级排序→分组；失败→错误态+重试；`/search/` 静态壳 `noindex`
- 不做：AI 搜索/复杂模糊/拼音

### 6.2 索引页筛选

内嵌过滤数据岛（仅筛选字段，不额外请求）；维度内 OR/维度间 AND；URL 全状态 `replaceState`；`popstate` 按 URL 重渲染；刷新/分享按 URL 初始化——03 §2.5 全套规则落地。

### 6.3 `/free/` 本地查找

数据岛含 `gameTitle/platform/type/日期/checkedAt/linkHealth/url`；`?q=`/`?platform=`/`?type=` 三参数+AND+清除；`?type=` 激活→统一结果列表、清空→五分区（05 §7.4）；未关联 Game 的活动照常可检索；生命周期实心徽标、链接健康描边徽标分轨。

## 7. 数据处理链路与构建流水线（阶段化重排）

### 7.1 处理链路（每阶段输入→输出→失败条件→责任方）

| 阶段 | 输入 | 输出 | 失败条件 | 责任方 |
|---|---|---|---|---|
| S1 环境准备 | lockfile | node_modules | 依赖装不上→中止 | 本地/平台 CI |
| S2 结构校验 | data/*.json + schemas/*.json | 合法记录集 | 阻断级错误→非零退出 | 本地脚本（Ajv） |
| S3 关联+资格 | S2 结果 + enums | 资格集合+反查表 | 必填引用缺失→非零退出；警告级→记录继续 | 本地脚本（自定义） |
| S4 生命周期计算 | 资格集合内 FreeOffer | lifecycle 标注 | 不失败（异常→uncertain） | 本地 lib（构建期权威） |
| S5 页面生成 | S3+S4 结果 | dist/ HTML | Astro 错误→非零退出 | Astro |
| S6 产物生成 | S5 结果 | 索引/sitemap/robots/redirects | 生成失败→非零退出 | lib+`@astrojs/sitemap`+脚本 |
| S7 产物检查 | dist/ 全量 | 验收报告 | 任一断言失败→非零退出 | 本地脚本 |
| S8 部署 | 通过的 dist | 线上版本 | 平台失败→保留上一版本 | CF Pages |
| S9 部署后验收 | 线上 URL | 验收结论 | 失败→回滚重发 | 人工 |

### 7.2 三级问题（与 04 §8.1 一致）

阻断（语法/必填/枚举/必填引用/重复 ID/slug）→非零退出不部署｜警告（悬空可选引用/死链/超核验/published 未达标）→记录继续｜维护提示（久未核验清单/外链抽查）→仅输出报告。可选字段缺失永不阻断。

### 7.3 产物检查断言（S7，任一失败=构建失败）

- `dist/` 无 `_demo` 渲染痕迹、无 draft/offline/未达标 slug 页面
- sitemap ⊆ 实有 HTML；索引项 URL 全部存在且唯一
- `search/` 带 `noindex` 且不在 sitemap
- `_redirects` 仅源自 `redirects.json`；**无自环/循环链/指向不存在目标**（P16 补充）
- 已结束活动页无领取 CTA

### 7.4 代表性异常用例（校验期望行为）

| 用例 | 期望结果 |
|---|---|
| 必填字段缺失 | 阻断，指明文件+字段 |
| `startDate>endDate` | 警告+前台 `uncertain`（04 §4.5/8.1） |
| `Entry.siteId` 指向不存在 Site | 阻断（必填关联） |
| `Tool.supportedGames` 含不存在 id | 警告+该关联忽略 |
| published 但未达标 | 警告+该页不生成，不进索引/Sitemap |
| `_demo:true` 记录在正式目录 | 无条件排除，不算错误 |
| slug 改了未登记 redirects | 产物断言发现旧 URL 断链→警告 |
| redirects.json 指向不存在 slug | 产物断言失败→阻断 |

### 7.5 Sitemap 生成方式（定案，取消"二选一"）

采用 **`@astrojs/sitemap`** 官方集成：输入为实际构建页面，`filter` 排除 `/search/` 与 `404`；`lastmod` 取数据 `updatedAt`。产物断言再验证 sitemap ⊆ 实有 HTML——自写生成器仅作备选保留，不作为并存方案。

## 8. SEO 与 URL 规范

### 8.1 元数据与结构化数据

- `title`/`description` 按模板规则生成，`seo.*` 字段覆盖优先（02 §5.2 模板例：`{中文名} {英文名} - 下载/MOD/报错修复 | 玩机索引`）
- canonical 全页统一 `<site.url+路径>`
- **JSON-LD（待实现，M5 交付）**：游戏页 `VideoGame`、工具页 `SoftwareApplication`、教程页 `Article`/`HowTo`（结构化 steps 天然映射 HowToStep）、全站 `WebSite`、详情页 `BreadcrumbList`——**仅填有数据支撑的属性，不虚构**（aggregateRating、offers 等无可靠来源不填）
- `/search/` `noindex,follow` 不进 sitemap

### 8.2 URL 规范（新增决策）

| 项 | 决策 |
|---|---|
| 尾斜杠 | 全站统一 `/path/` 形式；Astro `trailingSlash: 'always'`；canonical/内链/sitemap/redirects 一律带尾斜杠，禁止 `/path` 与 `/path/` 双形态并存 |
| 站点域名唯一源 | `config/site.json` 的 `site.url` → 构建期注入 `astro.config.mjs` 的 `site`；canonical/JSON-LD/sitemap/绝对外链一律由此派生 |
| `base` | 根部署 `/`；GH Pages 项目站点场景按平台注入 `/{repo}/`，资源/内链由 Astro `base` 自动前缀 |
| 静态输出 | `output: 'static'`，无 SSR 依赖 |
| 内链 | 模板内一律站内相对路径（经 `base` 解析），不手写绝对 URL |
| 404 | `404.html` 平台原生服务返回真实 404 状态码 |
| 重定向 | `redirects.json` 唯一源→`_redirects`（CF，301）+ meta-refresh 页（GH 备） |

### 8.3 图片

文字封面/占位图优先；不引远程游戏图；`cover` 缺失回退不破坏结构；日后用外部图须核实来源与使用条件；不为此引图片服务。

**不承诺收录**：只保证可抓取 HTML+规范元数据+sitemap 双站长平台提交；收录与否是搜索引擎的决定。

## 9. 免费活动时效与生命周期实现

### 9.1 时间规范落地（04 第五部分）

- 全站 `Asia/Shanghai`；`date` 与 `datetime` 区分；仅日期 `endDate` 按当日 23:59:59(+08:00) 前有效
- `checkedAt` 人工维护，**构建程序不改写**；`buildTime` 构建期注入，展示于 `/free/` 页头与页脚——三个时间概念永不混淆

### 9.2 双层判定的唯一逻辑保证

`lib/lifecycle.mjs` 一份**纯函数**实现 04 §4.5 判定表（输入：type/startDate/endDate/checkedAt/now/staleDays）：
- **构建期**：`astro build` 中 import 执行，渲染权威徽标与分区
- **运行期**：同一文件经打包进 client bundle，用 `data-*` 中的日期+当前时间复算——**同一源文件两端引用**，不是"两处各写一遍"，消除端间逻辑分叉

### 9.3 边界用例矩阵（判定预期）

| 情形 | 预期 |
|---|---|
| `now<startDate` | `upcoming` 未开始 |
| `now>endDate` | `ended` 归档，无领取 CTA，仅官方参考链接 |
| 无 `endDate` | `deadline_unknown`（未超核验时） |
| `startDate>endDate`/日期非法 | `uncertain` + 校验警告 |
| 仅日期 `endDate` | 按当日 23:59:59+08:00 判定 |
| 核验过期（未超 `endDate`） | `uncertain`（规则 4） |
| 已结束+核验过期 | `ended`（规则 2 优先） |
| 链接 `dead` | 徽标禁用+替代去向；生命周期结论不变 |
| 脚本未执行 | 构建期渲染的徽标/日期/提示全部静态可见，仍可读 |
| 页面久未重建 | 构建期快照+页头 buildTime+"以官方为准"文案兜底 |

### 9.4 触发重建

①手动：改数据→push→自动构建（主路径）；②定时（可选）：Actions cron 每日构建→CF 部署钩子或推 commit。cron 可靠性限制已如实说明（可能延迟、60 天无活动停用）；页头固定"最近构建 {buildTime}+定期人工更新"文案兜底，不承诺实时。

## 12. 维护流程与风险

**Git 工作流**：改数据→`npm run validate`→push→自动构建部署；下线=offline+push；slug 变更=字段+redirects.json（漏登记时产物断言告警）；回滚=CF 重发上一部署或 git revert；构建失败=不部署=线上无感知。**全部维护=改数据文件，无后台。**

| 风险 | 缓解 |
|---|---|
| 数据过期 | checkedAt+staleDays 徽标；可选 cron |
| 外链失效 | 构建期可选抽查标 suspect；反馈通道 |
| 收录不理想 | sitemap 双站长提交；不承诺 |
| 关联错误 | 校验阻断/警告分级 |
| 平台能力变化 | 双平台策略（§3 如实差异） |
| 构建失败 | 本地 validate 前置；失败不部署 |
| 依赖升级 | 依赖 ≤4，lockfile 锁定 |
| 个人时间不足 | "小而完整"可长期存在；不追求收录数量 |
| 重定向腐坏 | 产物断言查循环/不存在目标 |
