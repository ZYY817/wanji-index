## 2. M0a 成果处置

**复用（模式，非逐行拷贝）**：
- `eligibility.mjs`：六实体最低标准表 + `isEligible`/`filterEligible`——原样思路，M0 只实现判定函数本体
- `lifecycle.mjs`：纯函数判定表（五态）、仅日期→+08:00 端点、checkedAt+staleDays 过期兜底——与 M0a 相同的纯函数设计，供构建期与浏览器端共用（浏览器端使用场景属 M4+）
- `load.mjs`：glob 聚合 + `buildRelations` 反查模式
- `check-artifacts.mjs`：断言收集/非零退出模式
- URL 单源：`Astro.site`+`Astro.url` 生成 canonical（M0a §7.6 教训修正后模式）

**重新整理/新增**：
- `config.mjs`：新增——`loadSiteConfig` 含字段校验（name/url/base/staleDays 必填+格式），构建入口即失败
- 配置加载分两层：**`.astro` 内直接 `import cfg from 'config/site.json'`**（Vite 打包为数据）；fs loader 仅供 astro.config/scripts——*修复 M0 中新暴露的问题：fs 读取在 Astro 打包后 `import.meta.url` 指向 `dist/`，首次构建报 ENOENT，改 JSON import 后通过*
- `build-test.mjs`：新增——Windows 下 npm script 内联 `DATA_DIR=...` 不可移植（cmd 解析失败），改 Node spawn 注入 env
- 数据加载 `DATA_DIR` 可注入：`data/` ↔ `tests/fixtures-data/` 两棵 glob 树，测试构建完全隔离

**未复制**：`_m0a-verify/` 的测试页面（free.astro 等）、fixture 数据、`test-lifecycle.mjs`、`schemas/` 实验 schema——属 M1–M4 按规范重新实现。
