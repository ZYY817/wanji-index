## 1. 全局交互原则

| # | 原则 | 规则 |
|---|---|---|
| G1 | 确定性反馈 | 每次用户操作产生可预期、可说明的页面变化；无反应、无提示的操作不允许存在 |
| G2 | 诚实状态 | "没有数据 / 尚未核验 / 疑似失效 / 已失效 / 已结束"是五种不同状态，各有独立徽标与行为，绝不混用、绝不默认"有效" |
| G3 | 内外链区分 | 内链当前页跳转；外链新标签页打开并带 `↗` 与目标站点名；"链接可访问"不等于"资源安全"，时效性内容必须附"以官方页面为准"提示 |
| G4 | 空模块隐藏 | 无数据模块整块不渲染；但"无数据"与"数据待补充"在数据层是两个状态，页面均不造假填充 |
| G5 | 状态可分享 | 列表页的搜索词、筛选、排序同步到 URL 查询参数；刷新、分享、浏览器前进后退均还原相同视图 |
| G6 | 移动端同逻辑 | 移动端只改变控件形态（抽屉/全宽按钮），不改变任何业务规则、状态判定与操作结果 |
| G7 | 无死路 | 任何末端状态（无结果、失效、404）都提供至少一个有效去向或反馈入口 |

## 2. 导航与链接规则

### 2.1 顶部导航

| 导航项 | 目标地址 | 当前态判定 |
|---|---|---|
| 站点名「玩机索引」 | `/` | 点击回到首页，任何页面生效 |
| 游戏库 | `/games/` | 路径以 `/games/` 开头时高亮（含档案页） |
| 免费游戏 | `/free/` | 同上规则 |
| 资源站 | `/resources/` | 同上规则 |
| 工具库 | `/tools/` | 同上规则 |
| 教程与问题 | `/guides/` | 同上规则 |
| 搜索框 | 输入后回车/点击按钮 → `/search/?q={词}` | 常驻导航右侧，非导航项 |

当前态在导航项上以高亮 + `aria-current` 体现；`/search/`、`/about/`、`/404` 不高亮任何导航项。

### 2.2 面包屑与返回

- 仅详情页显示面包屑：`首页 / {所属索引} / {条目名}`，前两段为可点击内链，末段为纯文本。
- 页面不提供"上一页"式返回按钮——直达用户没有上一页，面包屑是唯一返回机制。
- 索引页（/games/ 等）不显示面包屑。

### 2.3 外部链接统一规则

| 规则项 | 行为 |
|---|---|
| 打开方式 | 一律新标签页（`target="_blank" rel="noopener noreferrer"`），全站一致 |
| 视觉标识 | 站点名/域名 + `↗`，与内链明确区分 |
| 附带信息 | 按钮旁或条目内展示核验日期；时效/风险内容附"以官方页面为准"或风险提示 |
| `待核验` 链接 | 可点击，带状态徽标——它仍是目前所知最佳地址 |
| `疑似失效` 链接 | 可点击，带警示徽标与一句提示（如"该链接近期可能无法访问"） |
| `已失效` 链接 | **不可点击**，按钮禁用态 + "已失效"徽标 + 反馈入口 + 替代去向（所属资源站主页或站内搜索建议） |
| 目标地址缺失 | 不渲染按钮，显示"地址待补充"纯文本——绝不渲染空链接 |
| 原站无法确认状态 | 在条目上加"原站状态待确认"说明，并在条目核验日期旁注明 |

### 2.4 移动端导航

- 导航折叠为汉堡按钮 → 全屏/抽屉菜单，菜单内为与桌面相同的 5 个导航项 + 搜索框。
- 点任一菜单项或遮罩区关闭菜单；页面切换后菜单必为关闭态。
- 桌面与移动的导航项、目标地址、当前态规则完全一致。

### 2.5 URL 状态与浏览器历史（全站统一）

| 情形 | 规则 |
|---|---|
| 输入搜索词 / 勾选筛选 / 切换排序 / 切换结果分类 tab | **`replaceState` 更新 URL，不产生新历史记录**——每个状态是可分享的"当前视图"，不是历史栈节点（否则每敲一个字符都产生一次历史） |
| 点击条目进入详情页 | 正常跳转，产生历史记录 |
| 全局搜索框提交（跳 `/search/?q=`） | 正常跳转，产生历史记录 |
| 详情页点浏览器"后退"返回列表 | 浏览器回到带参数的列表 URL；列表按 URL 参数重新渲染，恢复离开时的关键词、筛选与排序 |
| `popstate`（前进/后退） | 重新读取当前 URL 参数并重新渲染对应视图 |
| 刷新 / 打开分享链接 | 按 URL 参数初始化视图；无参数 → 默认视图 |
| 清空关键词/筛选 | `replaceState` 清掉对应参数，视图回默认 |

统一口径：**视图状态变化一律 `replaceState`，页面跳转才产生历史。** 各页涉及 URL 的章节均以本表为准。

## 3. 搜索交互（全站统一，供各页引用）

### 3.1 两种搜索形态

| 形态 | 位置 | 行为 |
|---|---|---|
| 全局搜索 | 顶部导航搜索框 | 提交 → `/search/?q={词}`（见 §11） |
| 页内即时过滤 | 各索引页（游戏库/资源站/工具库/教程库） | 输入即过滤当前列表，无提交动作，结果实时刷新；关键词以 `replaceState` 写入 URL `?q=`（历史规则见 §2.5） |

### 3.2 匹配规则（第一版，确定性）

- 大小写不敏感、首尾空格忽略、全半角归一。
- 匹配字段：名称 > 别名/英文名 > 简介关键词。名称命中优先展示。
- 仅子串匹配。**不做**拼音、模糊、纠错、AI 搜索（v1 外）。
- 无结果时的行为各页在对应章节定义，统一要素：明示"无匹配"、保留/建议关键词、给收录请求入口。

## 5. 游戏库 `/games/` 交互

| 交互 | 规则 |
|---|---|
| 即时搜索 | 输入即过滤；匹配中文名/英文名/别名（§3.2） |

| 控件显隐 | 某维度在全部数据中无有效取值时（如首批平台单一），该筛选控件不渲染，不做死按钮 |

## 6. 游戏详情页 `/games/{slug}/` 交互

按第二阶段模块顺序逐一定义。

| 模块 | 用户操作与行为 | 空态/异常 |
|---|---|---|
| 档案头 | 展示信息，无可操作项；可选封面缺失时用文字封面占位 | 图片加载失败 → 回退文字封面 |
| 速查条 | 存档/配置路径支持点击复制（点击复制按钮，成功给"已复制"提示 2 秒） | 无数据项不渲染该项 |
| 获取渠道表 | 点渠道行/按钮 → 新标签外链至商店页；每行展示平台/渠道类型/价格说明/核验日期 | 链接已失效 → 禁用+徽标+反馈入口+替代（商店主页或 /resources/{slug}/）；存在限时免费 → 表上方提示条（类型/截止时间/"以官方页面为准"），过期则提示条转为置灰"已结束" |
| 常见问题速查 | 带教程链接的条目 → 点击跳 `/guides/{slug}/`；纯短答条目 → 点击就地展开/收起答案（手风琴，默认收起） | 无数据 → 模块隐藏；版本不明的条目带"适用版本待核验"徽标 |
| MOD 与汉化 | 点资源入口名 → 新标签外链至**该站上本游戏的专区页**（Entry）；点所属站点名 → 内链 `/resources/{slug}/`（Site）。两条链接并列展示、各自标识 | Entry 失效但 Site 正常 → 入口禁用+徽标，站点内链仍可用作替代 |
| 工具与修改器 | 点工具名 → `/tools/{slug}/`；点官网按钮 → 新标签外链 | 无关联工具 → 隐藏 |
| 相关教程 | 点击 → `/guides/{slug}/` | 无 → 隐藏 |
| 相关游戏 | 点击 → 对应 `/games/{slug}/` | 无 → 隐藏 |
| 核验与反馈条 | 点击"信息有误/链接失效？"→ `/about/#feedback` | 必有，不隐藏 |

**版本不明确**：条目级"适用版本待核验"徽标，不阻塞展示与跳转。
**最低发布标准**：不满足标准的游戏**不生成页面**——这是构建期规则；用户手动访问对应 URL → 404 页。

## 7. 免费游戏 `/free/` 交互与状态规则

### 7.1 页面结构

五种固定分区：`永久免费`｜`限时领取`｜`免费试玩`｜`免费周末`｜`开源`（页内锚点分节或 tab，行为一致）。

**本地查找控件**（分区上方，行为见 §7.4）：关键词输入框 + 平台筛选 + 免费类型筛选 + "清除全部"。

条目卡统一包含：游戏名 / 来源平台 / 免费类型徽标 / 领取条件 / 截止时间（限免、免费周末必有）/ 核验日期 / 官方链接 / **生命周期徽标**（仅 `limited`、`weekend` 及带时间字段的 `trial`；`permanent`、`opensource` 不展示）/ **链接健康徽标**（全类型适用）。另设"实时追踪入口"区与折叠的"已结束"区。页头固定展示**本站最近构建时间**。

**数据范围**：分区与查找覆盖全部符合前台展示规则的 FreeOffer——含已关联 Game 的活动与仅有 `gameTitle`（对应游戏未收录）的活动，**不得因无 `gameId` 而排除**。

### 7.2 活动状态判定（生命周期 × 链接健康，双维度）

**生命周期适用范围**（先判类型，再判时间——与 `docs/04` §4.5 一致）：

| freeType | 生命周期徽标 |
|---|---|
| `permanent` / `opensource` | **不适用**：不进入生命周期判定，不展示"未开始/进行中/已结束/截止不明/状态待确认"徽标；仍受链接健康与"久未核验"提示约束 |
| `trial` | **条件适用**：记录含时间字段（`startDate`/`endDate`）时按下表判定；无时间字段按长期内容处理，不挂徽标 |
| `limited` / `weekend` | **适用**：按下表优先级判定 |

状态由两个**正交维度**构成，不得混为一谈：

- **生命周期**（先判定）：决定活动展示在哪个区、是否仍呈现为可领取操作
- **链接健康**（后叠加）：决定链接可用性与警示样式，不改变生命周期结论

**生命周期判定（自上而下，取第一个命中的规则）**：

| 优先级 | 条件 | 状态徽标 | 展示位置 | 链接行为 |
|---|---|---|---|---|
| 1 | 日期缺失/非法，或 `startDate > endDate` | 状态待确认 | 所在分区正常位 | 可点击，文案"查看活动页"；展示核验日期 |
| 2 | `now > endDate` | 已结束 | "已结束"区（构建期归档；运行时二次置灰） | **不呈现领取操作**；仅保留"官方活动页（参考）"次级链接 |
| 3 | `now < startDate` | 未开始 | 所在分区正常位 | 可点击，"查看活动页"；显示开始日期 |
| 4 | 已超核验周期（`checkedAt + staleDays < now`；阈值唯一配置源为 `config/site.json` 的 `review.staleDays`，按记录类型分档——时效活动 14 天/长期活动 90 天为当前建议值，最终参数见 `docs/06` §13 待确认；无论有无 `endDate`） | 状态待确认 | 所在分区正常位，带徽标 | 可点击；提示"信息久未核验，以官方页面为准" |
| 5 | 无 `endDate` 且未超核验周期 | 截止不明 | 所在分区正常位 | 可点击；徽标"截止以官方为准" + 突出核验日期 |
| 6 | `startDate ≤ now ≤ endDate` | 进行中 | 所在分区正常位，排序靠前 | 主按钮"前往领取 ↗"；显示截止时间 + "以官方页面为准" |

**链接健康（正交叠加，适用于任何生命周期）**：

| 链接状态 | 叠加行为 |
|---|---|
| 疑似失效 | 叠加警示徽标与一句提示（"该链接近期可能无法访问"），链接仍可点击 |
| 已失效 | 链接禁用 + "已失效"徽标 + 替代去向 + 反馈入口 |
| 原站状态无法确认 | 附加"本站无法确认原站当前状态"提示 |

**多条件同时成立时的判定结果**：

| 组合 | 判定结果 |
|---|---|
| 已超截止时间 + 核验信息过期 | 已结束（规则 2 先于规则 4）——归"已结束"区，核验过期不改变"已结束"结论 |
| 无截止时间 + 核验信息过期 | 状态待确认（规则 4 先于规则 5）——不默认有效 |
| 已结束 + 官方链接疑似失效 | 已结束归档 + 链接警示徽标；参考入口仍展示但不作领取操作 |
| 开始/截止时间异常（缺失、非法、start>end） | 状态待确认（规则 1） |
| 状态无法可靠确认（兜底） | 状态待确认——**不得默认仍然有效** |

**铁律**：活动状态无法可靠确认时，一律归为"状态待确认/截止不明"，**不得默认仍然有效**；已结束的活动不得继续呈现为可执行的领取操作。

### 7.3 三层时效保障（按修订版逻辑）

1. **构建时（权威）**：SSG 按 `endDate` 归档过期条目——信息准确的主要保障是定期重建。
2. **运行时（补充）**：浏览器按 `endDate` 二次置灰。仅在脚本正常执行时有效；脚本未运行（禁用 JS、爬虫快照、阅读器模式）或页面久未重建时，信息可能过期——因此**截止时间、核验日期与"以官方页面为准"提示必须以静态文本呈现**，不依赖脚本注入。
3. **明示限制**：定时重建属后续技术评估；未实现前，限时领取区固定文案"本页定期人工更新，最近更新 {构建日期}，领取前请以官方页面为准"。

### 7.4 本地查找与用户操作

**本地查找（客户端实现，无后端；字段与 `docs/04` Schema 一致）**：

| 控件 | 匹配/过滤对象 | 行为 | URL 参数 |
|---|---|---|---|
| 关键词输入框 | `gameTitle`（含未关联 Game 的独立标题） | 输入即过滤（防抖），大小写不敏感 | `?q=` |
| 平台筛选 | `platform`（活动来源平台枚举） | 多选，同维度 OR | `?platform=` |
| 免费类型筛选 | `type`（五种免费类型） | 多选，同维度 OR；未启用时按五种分区展示全部 | `?type=` |
| 清除全部 | — | 恢复默认视图并清掉对应 URL 参数 | — |

- **组合规则**：关键词 AND 平台 AND 类型；同一维度多值为 OR
- **URL 与历史**：控件状态按 §2.5 以 `replaceState` 写入 URL；刷新 / 分享 / `popstate` 均按参数还原视图
- **空态**：无匹配 → 明确空态 + 当前生效条件摘要 + "清除全部" + 收录请求链接
- **数据范围**：过滤对象为全部符合前台展示规则的 FreeOffer，含无 `gameId` 者（按其 `gameTitle` 匹配）——不依赖 Game 档案是否存在
- **边界**：本查找仅服务 `/free/` 页内；FreeOffer **不进入全站搜索索引**，与既定结论一致

**条目操作**：分区 tab/锚点切换 → 滚动定位；条目点击 → 新标签外链；`gameId` 已收录时卡片附"查看游戏档案 →"内链，无则仅外链；`permanent`/`opensource` 条目不展示生命周期徽标，但照常展示链接健康徽标。

## 16. 第一版功能分级

**A. 必须实现**：全局/页内搜索（确定性匹配）、筛选与排序、内链导航与外链跳转（新标签规则）、五态徽标与状态判定、空态与隐藏规则、免费活动状态判定与双层时效处理、移动端布局、反馈入口体系、URL 状态同步、404。

**B. 可以简化**：仅子串匹配；两种排序；同 tag 规则式相关游戏；数据为空时筛选器自动隐藏；构建时计算反向引用（关联游戏列表）无需运行时逻辑。

**C. 暂不实现**：账号/收藏同步、评论社区、复杂推荐、fuzzy/拼音/AI 搜索、自动下载安装、活动提醒订阅、后端表单、桌面客户端、任何变现功能。

## 18. 与第二阶段核对发现的补充说明（非矛盾，为补全）

1. **免费条目与游戏档案的关系**：限免条目可能对应未收录游戏——条目为独立轻量记录，仅当其 `gameSlug` 存在时附"查看游戏档案"内链；规则已在 §7.4 明确。
2. **平台筛选的含义**：第二阶段未定义"PC 平台"——明确为**获取平台**（Steam/Epic/GOG 等），非操作系统（操作系统筛选只存在于工具库）。
3. **构建时间展示**：/free/ 页头需展示站点最近构建时间，作为静态时效披露的组成部分。
4. **核验周期阈值**：唯一配置源为 `config/site.json` 的 `review.staleDays`（按记录类型分档，见 `docs/04` §4.10）；建议初始值=时效活动 14 天 / 普通内容 90 天 / 教程 180 天；最终数值列为 `docs/06` §13 参数级待确认项，本文档不另行硬编码。
