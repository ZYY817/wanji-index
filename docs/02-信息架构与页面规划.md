## 0. 全局决策（先于逐页规划）

### 0.1 实体模型与数据关系（高层级）

五类实体，关系如下：

```
Game（游戏）
 ├── 1—n  ResourceEntry（资源入口：某资源站上针对本游戏的具体页面）
 │         每个 Entry 指向 1 个 ResourceSite（多对一边上的具体资源）
 ├── n—n  Tool（工具，经 Tool.supportedGames 反向关联）
 └── n—n  Guide（教程/问题条目，经 Guide.games 关联）

ResourceSite（资源网站）：独立实体，如 Nexus Mods、SteamDB
Tool（工具）：独立实体，可引用 ResourceSite 作为官方获取渠道
Guide（教程/问题）：独立实体，可关联 Game 和 Tool
```

**关键区分**（对应说明书要求）：
- `ResourceSite` = 网站本身（Nexus Mods 是什么、能干什么）
- `ResourceEntry` = 该站上**针对某款游戏**的具体入口（"Nexus 的星露谷物语专区"），它是 Game 与 Site 之间的关联记录，存自己的 URL、说明、核验日期
- 两者分开存储：游戏页展示 Entry，资源索引页展示 Site，互不重复维护

### 0.2 全局约定

| 约定 | 决策 |
|---|---|
| URL slug | 英文小写连字符（`elden-ring`），中文名仅用于展示与搜索 |
| 核验状态枚举 | 后经 `docs/04` 拆为两个正交维度：内容核验 `reviewStatus`（已核验/待核验）× 链接健康 `linkHealth`（正常/待核验/疑似失效/已失效）——中文展示名沿用，存储枚举值与前台行为以 `docs/04` §4.2/§4.3 为准；未核验绝不标"已验证" |
| 免费类型枚举 | 固定五种：`永久免费` / `限时领取` / `免费试玩` / `免费周末` / `开源` |
| 封面图策略 | 页面支持可选封面；v1 使用原创文字封面或简洁占位图；后续若使用游戏官方图片，须核实来源与使用条件，并提供图片失效时的回退（占位图或隐藏）。不做"全站无图"硬性要求 |
| 空态总原则 | 无内容的模块**整块隐藏**，不显示"暂无内容"占位，绝不用虚构资源填充 |
| 最低发布标准 | 游戏页至少含简介+1条获取渠道，否则不生成页面、不进 sitemap |
| 反馈入口 | 每个详情页页脚固定"信息有误/链接失效？"链接，指向统一反馈方案（见 5.4） |
| 时间字段 | 所有资源条目带 `checkedAt`（最近核验日期），页面直接展示 |

## 输出一：完整网站地图

```
/（首页）
│
├── /games/                    游戏库（列表+筛选）
│    └── /games/{slug}/        游戏档案页（每款游戏一个独立 HTML）
│
├── /free/                     免费游戏索引（按免费类型分区）
│
├── /resources/                资源网站索引（分类导航+搜索）
│    └── /resources/{slug}/    资源网站详情（每个站点一个 HTML）
│
├── /tools/                    工具库（分类+筛选）
│    └── /tools/{slug}/        工具详情（每款工具一个 HTML）
│
├── /guides/                   教程与问题库（分类+筛选）
│    └── /guides/{slug}/       教程/问题详情（每条一个 HTML）
│
├── /search/                   搜索结果页（客户端渲染，noindex）
│
```

**一级导航**（顶部，常驻）：游戏库 / 免费游戏 / 资源站 / 工具库 / 教程与问题 —— 右侧全局搜索框。

**延后层级**（不进第一版）：独立分类落地页、标签聚合页、RSS/更新日志页。

## 输出三：逐页完整模块规划

### 3.1 首页 `/`

**页面目标**：3 秒内让用户知道"这是干什么的"，并用最少点击进入自己的目标路径。核心动作是搜索与分流，不是展示。

**模块顺序与内容**：

| # | 模块 | 内容与字段 | 用户操作 | 跳转 | 空态 |
|---|---|---|---|---|---|
| 1 | 顶部导航 | 站点名、5 个一级导航项、搜索框 | 点击导航/输入搜索 | 各索引页 | — |
| 2 | Hero 区 | 一句话定位语 + 大号搜索框（占位提示"搜游戏名、报错、工具…"） | 输入搜索词 | `/search/?q=` | — |
| 3 | 需求分流卡（5 张） | 「找游戏」「找免费」「找 MOD/汉化」「找工具」「游戏出问题」各一句说明 | 点击卡片 | `/games/`、`/free/`、`/resources/?cat=mod`、`/tools/`、`/guides/` | — |
| 4 | 精选游戏档案 | 完成度最高的 6–8 款游戏卡片（名称/类型/一句话简介/资源数徽标） | 点击进档案 | `/games/{slug}/` | 数据不足时整个模块隐藏 |
| 5 | 免费游戏快报 | 当前有效的免费条目 3–5 条（游戏名/免费类型徽标/平台/截止时间） | 点击领取入口或"查看全部" | 原站链接、`/free/` | 无有效限时活动时：隐藏活动列表，模块保留并展示实时免费游戏信息源入口（链至 `/free/` 追踪区） |
| 6 | 热门工具速览 | 4–6 个高频工具（名称/用途一句话/适用说明） | 点击 | `/tools/{slug}/` | 隐藏 |
| 7 | 最近更新 | 全站最近新增/核验的 5–8 条记录（条目名/类型/日期） | 点击条目 | 对应详情页 | 隐藏 |
| 8 | 页脚 | 收录原则一句话、关于链接、反馈入口、版权行 | 点击 | `/about/` 各锚点 | — |

**设计意图**：搜索→分流→样板→时效→信任。弱化大 banner 与资讯流；"精选档案"承担"展示这个站长什么样"的示范职能；"最近更新"承担"这个站活着"的信任职能。

### 3.2 游戏库 `/games/`

**页面目标**：让用户在全部收录游戏中快速定位或浏览。

**模块**：
1. 页头：标题 + 收录数量（"已收录 N 款"）
2. 工具行：本页内即时搜索框（匹配中文名/英文名/别名）＋ 类型筛选（多选 tag）＋ 平台筛选 + 排序（名称 A–Z / 最近更新）
3. 游戏列表（卡片式）：每卡 = 可选封面缩略图（v1 文字封面/占位图）、名称（中/英）、类型 tag、一句话简介、已收录资源计数徽标（如"MOD 3 · 工具 2 · 教程 1"）、核验状态点
4. 空态：无匹配时显示"未收录"提示 + 相近名称建议（如有）+ "提交收录请求"反馈链接

**v1 必须实现**：即时搜索、类型筛选、名称/时间排序。平台筛选若首批数据单一可隐藏该控件（控件随数据出现，不做死按钮）。

### 3.3 游戏档案页 `/games/{slug}/`（核心页面）

**页面目标**：一页回答玩家对这款游戏的全部问题——去哪买、免费吗、MOD 在哪、报错怎么办、存档在哪。

**模块顺序**（自上而下）：

| # | 模块 | 展示字段 | 展示条件/空态 |
|---|---|---|---|
| 1 | 档案头 | 可选封面图（v1 文字封面/占位图）、中文名、英文名、别名（小字）、类型 tag、平台徽标、2–3 句简介 | 必有 |
| 2 | 速查条 | 存档路径、配置文件路径（若有）、首发年份 | 有数据才显示该项 |
| 3 | **获取渠道表** | 平台名 / 渠道类型（购买·免费·试玩·订阅）/ 价格说明 / 链接按钮 / 核验日期 | 必有≥1条，否则页面不发布；存在限时免费时表格上方追加醒目提示条（含截止时间，过期自动转为"已结束"样式） |
| 4 | 常见问题速查 | 3–5 条"现象→一句话方向"，每条链到教程详情或展开短答 | 无数据整块隐藏（差异化模块，熟的游戏才填） |
| 5 | MOD 与汉化 | 资源入口列表：资源名 / 所属站点（内链至 `/resources/{slug}/`）/ 一句话说明 / 外链按钮 / 核验日期 | 无则隐藏 |
| 6 | 工具与修改器 | 关联工具卡：工具名（内链 `/tools/{slug}/`）/ 用途 / 适用版本说明 / 官网按钮 | 无则隐藏 |
| 7 | 相关教程 | 教程条目列表（内链 `/guides/{slug}/`） | 无则隐藏 |
| 8 | 相关游戏 | 同类型游戏 ≤6 个卡片 | 无则隐藏 |
| 9 | 页脚信息条 | "本页最近核验 YYYY-MM-DD · 信息有误/链接失效？"→ 反馈 | 必有 |

**模块间跳转关系**：MOD 区条目 → 资源站详情（内链）+ 原站（外链）；工具区 → 工具详情（内链）；FAQ/教程区 → 教程详情（内链）；相关游戏 → 游戏档案（内链）。外链按钮统一带站点名与 ↗ 标识，视觉上与内链区分。

### 3.4 免费游戏索引 `/free/`

**页面目标**：按免费类型准确分区，**绝不让过期信息看起来像有效活动**。

**模块**：
1. 页头 + 五种免费类型的定义说明（各一句话）
2. 类型分区（页内分节或 tab）：`永久免费`｜`限时领取`｜`免费试玩`｜`免费周末`｜`开源`
3. 每区条目卡：游戏名 / 来源平台 / 免费状态徽标 / 领取条件一句话 / 截止时间（限免与免费周末必有）/ 原始链接 / 核验日期
4. "实时追踪入口"区：IsThereAnyDeal、SteamDB、Epic 免费游戏页等外链——**这是本页的可维护性兜底**（手工条目覆盖不全时，用户始终有实时去处）
5. 已结束活动区：默认折叠，按结束日期倒序，条目置灰标"已结束"

**过期处理（无后端方案，分层，运行时校验仅为补充）**：
- 构建时（权威处理）：SSG 读取 `endDate`，已过期条目自动归入"已结束"区——信息准确性的主要保障是定期重建
- 运行时（补充手段）：浏览器校验 `endDate < now` 并将过期条目置灰。**仅在脚本正常执行时有效**；若站点长期未重建、脚本未运行（禁用 JS、爬虫快照、阅读器模式），页面仍可能展示过期信息——因此限时条目必须同时展示核验日期与截止时间，并提示"以官方页面为准"，让用户可自行辨别
- 定时重建（如 GitHub Actions cron 每日构建）：**纳入后续技术实施评估**；若未实现，限时领取区须以固定文案明示"信息更新频率受限，领取前请以官方页面为准"

### 3.5 资源网站索引 `/resources/`

**页面目标**：按用途浏览/检索资源站点本身（不是某游戏的具体入口）。

**模块**：
1. 分类导航条（8 类，计数徽标）：正版商店 / 免费与试玩平台 / 独立游戏平台 / MOD 社区 / 汉化与语言 / 攻略与百科 / 补丁与官方支持 / 其他实用
2. 即时搜索框 + 排序（名称/最近核验）
3. 站点条目列表：站点名 / 分类徽标 / 一句话简介 / 语言与费用说明 / 关联游戏数 / 核验状态 / "详情"内链 + "访问"外链
4. 空态：分类无条目时该分类整组隐藏

### 3.6 资源网站详情 `/resources/{slug}/`

**模块**：站点名+简介 / 类型与费用模式 / 主要用途（2–3 条）/ 语言 / 官网入口（主按钮）/ 使用限制与风险提示（如"部分资源需登录""注意区分官方与转载"）/ **关联游戏列表**（该站被哪些游戏档案引用，内链回游戏页——体现 Site↔Game 多对多）/ 最近核验日期 / 页脚反馈条。无关联游戏时该列表隐藏。

### 3.7 工具库 `/tools/`

**模块**：分类导航（MOD 管理器 / 存档工具 / 性能监测 / 游戏管理辅助 / 修改器官方渠道 / 兼容与排障）+ 即时搜索 + 筛选（适用系统、是否关联具体游戏）+ 工具列表卡（名称/用途/系统/费用/核验状态/详情内链+官网外链）。空态同资源索引。

### 3.8 工具详情 `/tools/{slug}/`

**模块**：名称+简介 / 主要功能列表 / 适用系统徽标 / 支持游戏（内链游戏档案）/ 版本与兼容说明 / **官方获取入口**（主按钮，标站名）/ 安装使用要点（3–5 步简述，完整教程外链或链到站内 guide）/ 已知限制与风险提示（如"仅支持单机""联机使用可能封号"）/ 相关教程 / 最近核验 / 反馈条。功能/兼容信息不确定时标"待核验"，不写猜测结论。

### 3.9 教程与问题库 `/guides/` + `/guides/{slug}/`

**列表页**：分类导航（安装运行 / 启动闪退 / MOD 安装与冲突 / 存档备份恢复 / 设置与兼容 / 性能排查）+ 搜索 + 关联游戏筛选；条目卡 = 标题 / 分类 / 关联游戏 / 核验日期。

**详情页模块**：
1. 标题 + 类型徽标（教程/问题排查）+ 关联游戏 + 适用版本/系统
2. **问题描述**：现象、报错原文（若有）、触发条件——报错原文原样收录，因为这是用户搜索词
3. **排查步骤**：有序步骤，每步含操作+预期现象，标注来源链接
4. 预期结果 / 若无效怎么办（下一步去向）
5. 信息来源（PCGamingWiki/官方文档/社区帖，外链）+ 核验日期 + 反馈条
6. 底部：关联游戏卡、相关教程

**红线**：未经验证的猜测不写成确定方案——只收录有来源或亲测的步骤，把握不足的步骤标"社区反馈方案，未核验"。

### 3.10 搜索结果 `/search/`

**模块**：搜索框（回填 q）→ 结果分类 tab（全部/游戏/资源站/工具/教程，各带计数）→ 分组列表：命中游戏卡排最前，其次工具/资源站，教程与问题条目最后。匹配规则（客户端）：名称 > 别名 > 简介关键词；报错查询靠 guides 的关键词字段命中。

**异常态**：无结果 → 显示"未找到"、站内热门搜索建议、"提交收录请求"链接；拼写偏差 → 不做 fuzzy 承诺，靠别名覆盖常见错写；同名游戏 → 卡片展示类型+年份消歧。整页 `noindex,follow`。

### 3.11 关于与收录 `/about/`

分区（锚点）：网站介绍 / 收录标准（可信来源判定规则明文）/ 核验原则 / 版权与第三方资源声明 / 失效反馈方式 / 联系方式。

## 输出四：核心用户路径

**路径 1：搜游戏→找到官方渠道**
首页搜索框输"星露谷"→ `/search/` 顶部命中游戏卡 → 进 `/games/stardew-valley/` → 获取渠道表点"Steam ↗"→ 出站到达商店页。
异常：游戏未收录 → 无结果页给"提交收录请求"；链接失效 → 页脚反馈条。

**路径 2：找免费游戏→领取**
导航点"免费游戏"→ `/free/` → "限时领取"区 → 看条目卡（平台/Epic/截止 10-30）→ 点原始链接 → 官方页领取。
异常：活动刚过期 → 条目已被运行时校验置灰标"已结束"，用户可看到实时追踪入口区继续找；全部过期 → 分区显示"本周暂无，看实时追踪 →"。

**路径 3：游戏详情→MOD/工具**
档案页 MOD 区 → 点"Nexus Mods 专区"（Entry）→ 直接到站外游戏专区；或点站点名 → `/resources/nexus-mods/` 了解这个站；工具区 → `/tools/{slug}/` 看使用说明 → 官网下载。
异常：某游戏未收录 MOD → 该模块不存在，页面不显得残缺（隐藏策略）。

**路径 4：搜报错→完成排查**
搜索框输"0xc000007b"→ 结果页"教程/问题"分组命中条目 → 详情页按步骤操作（如用 DirectX Repair 修复）→ 预期结果验证。
异常：报错未收录 → 无结果页 + 收录请求；步骤无效 → 详情页"若无效"段给下一步去向。

**路径 5：发现失效→反馈**
详情页点"信息有误/链接失效？"→ 跳 `/about/#feedback` 看反馈方式 → 通过 GitHub Issue 模板（预填页面路径）提交；无 GitHub 账号的用户走备用渠道 → 维护者更新数据并重建站点。
异常：备用渠道为预留的免登录第三方表单（具体服务实施阶段选定），邮箱兜底。

## 专项规划

### 5.1 模板复用（页面复用方案）

全站 8 个模板：`home` / `game-detail` / `resource-detail` / `tool-detail` / `guide-detail` / `*-index`（4 个索引页共用列表框架，仅数据与筛选项不同）/ `search` / `about`。新增游戏 = 加一条 Game 数据 + 其 Entry 数据，SSG 自动生成页面并刷新相关页（站点详情的"关联游戏列表"等）的反向引用。

### 5.2 SEO 规划（本阶段定要求，不实现）

- 每个实体一个独立 HTML，`title`/`description` 有模板化规则（如游戏页：`{中文名} {英文名} - 下载/MOD/报错修复 | 玩机索引`）
- 全页 canonical；`/search/` 设 `noindex`
- 结构化数据：游戏页 `VideoGame`、工具页 `SoftwareApplication`、教程页 `Article`/`HowTo`、全站 `WebSite`+面包屑
- `sitemap.xml` 构建时生成（只收录满足最低发布标准的页面）+ `robots.txt` 指向 sitemap
- 内链：档案页↔工具/站点/教程双向互链；首页与索引页构成主干
- 空页面控制：不满足最低内容标准的数据不生成页面、不进 sitemap
- 部署后：百度站长平台 + Google Search Console 提交 sitemap

### 5.3 移动端结构要求

- 首页：单栏，搜索框置顶，5 张分流卡两列栅格排列（2+2 后第 5 张「游戏出问题」独占整行）
- 详情页：模块顺序不变单栏堆叠；获取渠道表转卡片式行；外链按钮整宽可点
- 筛选器：索引页筛选收成"筛选"按钮展开的抽屉/下拉，不用常驻横条
- 长列表：卡片化、分页或"加载更多"，避免超长滚动
- 表格类（获取渠道/速查条）：窄屏降级为键值列表

### 5.4 反馈方案（无后端，已定案）

- 主渠道：**GitHub Issues** + Issue 模板（各详情页反馈链接带 `?template=` 与页面 slug 预填）
- 备用渠道：**免登录第三方表单**（面向无 GitHub 账号的国内用户，低门槛）；具体表单服务在实施阶段选定，当前仅预留接入位置
- 兜底：联系邮箱，写进 `/about`

### 5.5 首批内容规模（v1 数据目标）

10–15 款游戏档案（每款 ≥1 获取渠道 + ≥2 资源入口）· 15–25 个资源站 · 10–15 个工具 · 5–10 条教程/问题条目 · 免费区各类型若干示例条目。
